# 分屏尺寸记忆与本地衔接

我在23款唐 DM-i 冠军版平台21上使用嘟嘟桌面分屏，遇到过同一方向有不同宽度的分屏窗口，以及切换时短暂的拉伸。这次沿用主干 CarPlayViewAreas 和 showViewArea，不替换旋转、侧边栏和固定 Dock 的实现。

原来每个方向只保留最后一个窗口比例，现在在窗口稳定一秒后最多保留三个有效比例，像素级抖动会合并；下次从全屏连接时一并声明，按最接近窗口的形状选择。主屏换区域继续使用当前会话，不重建仪表。排队的旧窗口尺寸在应用前再次对照当前 View 尺寸，避免旧事件选择错误区域。

切换区域成功发送后，仅在取得有效快照时用本地最后一帧做短暂衔接；SurfaceView 或抓图失败时不启用遮罩，沿用主干原生切换。有可用快照时至少显示150毫秒，随后主屏有新呈现帧就让出，最长1200毫秒。截图只在内存中保存，隐藏时丢弃引用。显示衔接帧前先释放旧触点，期间仅暂停 CarPlay 触摸，隐藏后从新的按下恢复，防止按着旧画面误点新区域；设置手势仍可使用。这个条件只说明本地视频继续呈现，不代表iPhone已确认新的区域；主干的固定画布没有旧自用版 Adaptive H264 的几何确认回调，因此没有移植那套协议或用输出宽高冒充确认。全新或超出声明范围的分屏尺寸仍按主干的全屏区域回退，新的历史在下次连接使用。

本地测试覆盖多尺寸、横竖方向、Dock、侧边栏、旧超时取消和有界衔接，并生成中文自绘合成截图。相关自用功能已在我自己的23款唐 DM-i 冠军版、21控制器上实测。合并后的连接、首帧与连续分屏切换仍需补充同一组合的实车回归日志。
