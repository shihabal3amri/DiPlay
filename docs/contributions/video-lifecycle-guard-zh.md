# 视频解码器启动与释放保护

我在23款唐 DM-i 冠军版平台21上遇到过解码器创建和释放交接卡住的情况。主干现在已经有独立解码线程、异步关闭、Surface 交接和实际退出通知，这次保留这些实现，补充一组可以单独启用的准入保护。

“高级 → 媒体”增加“视频解码器交接保护（实验性）”，默认关闭，下次连接生效。开启后，同进程的视频解码器启动与释放依次执行；工厂忙碌时，其他启动最多等待750毫秒，随后延后一秒再尝试，避免不断创建候选解码器。创建、配置、启动和发布之间都检查工作线程是否已经关闭，以及上一阶段是否超过五秒。卡住的原生调用没有返回时，租约仍由它持有；不会把“等超时”当作已取消或已释放。

保护只管视频启动和释放，不把正常主屏解码或音频、通话、麦克风处理塞进这道门。另一个仪表或镜像的申请被拒绝时，不关闭健康主屏，也不删去镜像、低延迟、HEVC、平滑视频等现有功能。释放保留真实对象的所有权，直到轮到它清理，不靠遗失引用假装完成。代价是原生调用永久卡住时，新的视频启动和排队清理也会等待；已有播放不受这道门直接影响，但当前设备的驱动仍可能有自己的全局锁。

本次没有移植自动进程重启，也没有重启系统媒体服务、停止任何车机服务、改帧率或 Wi-Fi。这不是资源冲突的根治，也不能确认原车服务是否回收资源。相关功能的自用原型已在23款唐 DM-i 冠军版平台21上完成实车验证；本次公共移植分支尚未安装上车，仍待本分支的实测报告与日志。测试覆盖准入互斥、超时不抢占、阶段间关闭、清理保留所有权、健康主屏继续处理帧、默认关闭与九种语言设置，以及中文窄屏与全宽大字体合成截图；原有音频优先和视频生命周期测试随完整 CI 一起跑。
