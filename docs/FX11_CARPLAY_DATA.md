# FX11 车辆数据与 xcertplay 2026-10-14 更新合并

## 基线与移植范围

- DiPlay：`c30d3f0df18dd132739d864a9e054c73b3d57d8c`，保留此前本地博越 L / Ultra、Geely 车标和禁用 App 更新提示改动。
- xcertplay：`551895a..8b01399a17ef8b3193931a2ff4ed93b410a73570`。
- 按接口移植，未整体替换 DiPlay：采用 Location selector/interval 解析、重复 NMEA 参数、部分车辆状态能力声明/订阅、源时间戳与采样生命周期设计。
- 保留 DiPlay 的 BYD 电量、Wh、充电接口及多样本 PASCD；不会用 xcertplay 较小的数据模型覆盖这些能力。
- 不移植 xcertplay 主界面改版或 Android CarPropertyManager 读取层。DiPlay 已有显示区域切换逻辑；本次不替换显示/触控实现。
- 此数据通道属于普通 iAP2，不补齐 Apple Ultra CAF 配置或 Local UI 渲染。

## 开启

1. 设置 → 车辆 → 车型适配 → 吉利博越 L（FX11）。
2. 设置 → 高级 → 博越 L 仪表显示（实验性）→ **FX11 车况发送到 iPhone（实验性）**。
3. 默认关闭。修改后点击“立即重新连接”，或下次重新连接 CarPlay 后生效。
4. 此项与 Ultra、仪表地图及 GPS 位置共享独立；没有 GPS 定位也能响应手机车速请求。
5. 同卡片“仪表连接状态”显示车辆源和数据通道诊断。缺少 VHAL 类、权限或属性时保持不可用，不发送模拟值。

## 信号与发送

| 信号 | FX11 来源 | 发送形式 | 校验 |
|---|---|---|---|
| 车速 | 标准 VHAL `0x11600207`，m/s | iAP2 `0xFFFB` / `$PASCD`，最终单位 m/s | 原始事件时间与读取时间均不超过 2 秒；拒绝未知、非有限和超范围值 |
| 挡位 | FX11 `557874334`，0=P、1=R、2=N、3=D | PASCD 的挡位字母 | 与有效车速配套；未知挡位不发送，不能套用 Android 标准挡位位掩码 |
| 车外温度 | 标准 VHAL `0x11600703`，°C | `0xA101` 参数 4，带符号整数 °C | 有效范围与时间检查；仅声明和发送真实可用字段 |
| SOC / 电动续航 | 无已验证的 FX11 映射 | 不声明、不发送 | 不把标准总续航冒充电动续航，不解码未知厂商 BYTES |

- 使用 HIDL `get` 和属性配置读取；没有 VHAL 写入。
- 握手线程最多等待 2 秒预检数据源，只声明预检可用的字段；若当时没有数据，恢复后需重新连接以重新声明。
- GPS 只发送手机请求的 GGA/RMC，车速仅在 selector 4 请求后发送；每类报文遵守手机的最小间隔，最快 1 秒。
- 每条 NMEA 句子作为独立的参数 0 编码，避免将多条句子合并成一个参数。
- 车辆状态只在手机 `0xA100` 请求后发送，停止消息为 `0xA102`，周期 30 秒；暂时无数据也退避，不空转。
- 车速与车辆状态订阅独立：停止其中一个不会错误关闭另一个。最后一个订阅停止后关闭 FX11 读取器；控制器关闭时释放全部资源。
- 无线蓝牙引导链路不声明/发送这些数据；实际在无线 iAP2 隧道或有线控制链路处理。
- 获取失败/断线会清除缓存。普通断线按现有 FX11 源逻辑重试；Binder 调用超时会停止该读取器，需重新连接，避免累积阻塞线程。

新增自动测试覆盖单位、FX11 挡位、原始时间戳、陈旧/无效数据、双订阅释放、预检释放、能力声明、请求筛选、发送间隔、断开和 BYD 电量兼容；完整测试命令见 AGENTS.md。
