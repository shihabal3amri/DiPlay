# v31：水温来源、封面保留、地图尺寸和长标题

## 水温显示 — 原因与验证边界

v29/v30 只读取 Android 标准 ENGINE_COOLANT_TEMP（291504897 / 0x11600301）。保存的 FX11 v23–v25 实车诊断均显示该属性 config missing、never accepted，所以仪表显示未知值，不是把实际水温格式化丢了。

新增只读 ECARX ISensor 的 SENSOR_TYPE_ENGINE_COOLANT_TEMPERATURE（1052416）后备来源：ICar.getSensorManager → isSensorSupported → getSensorLatestValue。接口声明来自本地 GInputBridge adaptapi 源码 ISensor.java；它是冷却液温度接口，不使用 ENGINE_OIL_TEMP、外温或水温告警枚举冒充温度。

在后台线程按 500ms 读取，仅接受 active 能力及 -40～215°C 内的有限值；不支持时保留连接、30 秒重新检查；断开、异常、读数过期时清除。标准接口存在有效值时优先保留标准来源。日志包含原始值、来源、读数年龄与失败原因。尚未连接实车，ECARX 属性是否在这辆 FX11 上可读、单位和原厂读数是否一致仍需验证，不能保证本包水温已经实车修好。

## 音乐封面

之前每次播放状态更新都向仪表发布缓存查找结果；缓存淘汰、重复图片解码失败或元数据校正造成缓存缺失时，会把仍有效的当前封面覆盖成 null，显示默认音符。

现在仅在歌曲标题、歌手、专辑、来源和图片传输 ID 均未变化时保留已有有效封面。播放进度、暂停、时长校正不清空封面；新歌、新图片 ID、断开或元数据清空不沿用旧封面。不会持有超过一张当前快照之外的额外图片，也不回收共享图片。诊断增加 coverValid、retainedCoverUpdates、lastCoverChange，不记录歌曲文本或图片内容。本地回归覆盖可复现的缓存缺失场景；用户实车此次封面消失的触发原因尚待诊断确认。

## 仪表地图尺寸

设置 → 高级 → 博越 L 仪表相关设置 → 仪表地图尺寸。小、中、大、超大分别向 iPhone 报告 300、250、200、150mm 宽度；宽度越小，请求的地图文字和图标越大。默认“大”（200mm）保持之前的请求值。

只修改仪表副屏的物理尺寸声明，像素画布、地图窗口、safeArea、导航与音乐布局保持不变，主屏 CarPlay 的尺寸设置独立。三套仪表及原厂叠加模式均支持。修改仅标记需要重新连接，不自动断开；重新连接后由 iOS/地图应用决定实际绘制比例，不能保证所有导航应用缩放幅度完全相同。

## 长歌名和歌手

三套自定义仪表及原厂叠加音乐卡片均使用裁剪区域中的横向滚动。能放下的文字静止；过长时开头停留 1.5 秒，以每秒 28 个设计像素逐步展示末尾，末尾停留 1.5 秒，然后回到开头循环。歌曲变化时重新开始，播放进度更新不重置动画。音乐文字在自己的区域内绘制，不覆盖刻度和其他数据，视图不可见时不请求连续动画帧。

## 保留

保留三套仪表、普通 CarPlay、v29 经典音乐圆盘与底栏、原厂叠加实验、Geely 图标、更新提示设置、认证身份和资源。AutoHold 和车道居中等未确认的车辆状态继续显示未知或隐藏；未增加任何车辆属性写入。
