# FX11 叠加模式与档位修复（v23）

## 实车故障证据

2026-10-18，FX11_LOW / 50420982：

- v22 仪表诊断：`style=OEM_OVERLAY`，Display 4 首帧完成，`DIM property 561023759 not advertised; no write; writeAttempted=false`。
- CarPlay 日志中普通地图流 111 持续接收和渲染；Android display 4 截图包含真实地图。原厂没有叠加，是模式请求在目录检查时被阻止，不能归因于地图流未收到。
- `dumpsys car_service get-property-value 0x21708b0f 0` 返回状态 0、区域 0、16 字节 PA_IntBase `[1,0,0,0]`，表示有效原厂模式 0。
- 档位 `0x21407c9e` 也不在目录中，但直接读取返回状态 0、区域 0、INT32 `[0]`；标准 GEAR_SELECTION / CURRENT_GEAR 均返回 `[4]`，按各自枚举都表示 P。
- 这里只读取了当前档位；R/N/D 的实车切换未验证。

原始证据保存于 `outputs/fx11-v23-investigation/`，包含缓存诊断、直接读取结果和 Android 显示层截图。

## 修复

1. 允许读取已核实的固定档位属性 `557874334`，沿用 0=P、1=R、2=N、3=D。无效枚举、失败、不可用和过期仍显示未知，不拿 Android 标准位值套用这个枚举。
2. 叠加模式仅对固定反馈 `561023759` 和固定命令 `557876790` 允许目录缺失。目录已有的访问权限、区域限制和重复配置仍会阻止请求。
3. 目录缺失时必须先直接读取有效 0/3 反馈；空载荷、错误属性/区域、不可用、状态 1 或未知枚举均不允许写入。
4. 仍由用户明确点击开关或按 MODE 发起，单次最多写一次 0/3 并回读确认；不增加保活或自动重试，不更改旧三套仪表的 ECARX 0/1 通道。

## 验证与使用

新增目录缺失时的桥接测试、非法反馈禁止写入测试及档位直接读取/失效测试。最终构建和安装结果以输出目录的 `verification.json` 与 `installation.json` 为准。

安装后选择“原厂仪表叠加（实验性）”，连接普通 CarPlay，按 MODE 开启。MAP 流、VHAL 返回状态和物理仪表合成分别验证；回读成功不能单独证明透明合成可见。

## 后续实车结果

v23 用户确认 MODE 后地图出现、档位正确，但原厂圆盘没有保留，地图之外仍为黑色。因此 v23 解决的是模式请求被目录检查阻止，不是已经完成原厂透明合成。不要将地图可见或 0/3 回读成功记为叠加验收通过。后续调查见 v24 文档。
