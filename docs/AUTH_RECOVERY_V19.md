# v19 本地认证缓存恢复

## 已确认与未确认

用户反馈覆盖安装 v18 后仍提示缺少 MFi 证书。
已逐字节检查交付的 v18：`identity.pk8` 与 `certificate.p7b` 均存在，和能连接的 v10 完全一致。
APK 签名、包名也一致，因此不能把此提示直接认定为打包丢证书或更新清空数据。
当前只有模拟器连接，尚未取得车机这次失败的日志，真实车机根因未确认。

发现的代码缺口：旧 Bootstrap 只在整个认证目录不存在时从 APK 安装。
目录已经存在但为空、文件损坏、两份文件不匹配时，后续覆盖安装不会修复，反复显示同一认证错误。

## 修复

- 校验现有本地认证；完整且有效的认证继续使用，不更换已有身份。
- 校验失败时，在应用私有临时目录读取安装包内的认证资源，检查解析、P-256 曲线及证书与私钥签名匹配。
- 验证成功后才替换缓存；先备份旧目录，再切换完整目录。中断后可以恢复上一份认证或继续已校验的临时目录。
- 包内文件缺失或不匹配时保留旧缓存，继续明确失败，不转用其他认证服务或伪造成功。
- 不修改认证方式选择、手机配对或车辆设置。USB／I2C／远程认证流程保持原样。
- 诊断报告增加实际认证方式、Bootstrap 结果、包内资源可用性和已安装文件长度。不给出任何密钥或证书内容。

## 使用

直接覆盖安装 `DiPlay-HUD-Test-FX11-Auth-Recovery-v19-20261017.apk`，然后打开 DiPlay。
无需卸载或清除应用数据。如果仍提示失败，导出诊断，重点检查 `Authentication target` 与 `Authentication bootstrap`。
只有车机日志或实际重新连接成功，才能确认此次问题是否属于本修复覆盖的缓存异常。

保留 v18 的“超大／最大”CarPlay 尺寸、v17 导航 Opus 回退、三套仪表与 FX11 适配。
完整验证结果、源码差异和模拟器复现记录见交付目录。
