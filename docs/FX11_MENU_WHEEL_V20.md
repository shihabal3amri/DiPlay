# FX11 原厂菜单状态驱动仪表翻页（v20 测试版）

本版新增只读 DIM 菜单反馈监听。保留 MODE 的原厂／自定义三屏切换、原先的翻页键绑定与 DTE 候选监听、三套仪表、普通 CarPlay、v19 认证修复、导航声音修复和界面放大设置。

## 使用行为

- 开启博越 L、方控和任意自定义仪表时自动启动，不需要重新学习 MENU。
- 原厂 DIM 回报菜单打开（tab 0/2/3/4）后，短按下一曲向后翻页，上一曲向前翻页。一次短按只切一页，重复回调与长按不翻页，也不额外向 CarPlay 发送切歌命令。
- Midnight、Replica：音乐 → 导航 → 胎压；反向循环亦可。Panorama 保持地图，仅音乐／胎压卡片轮换。
- 原厂回报菜单关闭（tab 5）后，回到既有媒体按键策略。车载蓝牙音频仍由原厂 AVRCP 管理，DiPlay 不重复发送媒体命令。
- 电话页（tab 1）、不识别的状态、连接断开、等待首次状态时不启用这项翻页。控制中心事件使缓存失效，等待新的页签反馈；电话／媒体控制中心工作时不翻页。
- MODE 的优先级不变。按键学习期间不执行页面或媒体动作。历史上将上一曲／下一曲单独学习成翻页键的设置，也必须通过本次菜单状态判断。
- 只观察原厂按键，不拦截音量键，不强行改变原厂菜单或控制权，也不注入按键。原厂是否同时处理上一曲／下一曲需实车确认。

## 已确认的静态证据与限制

本车此前提取的 `oneOS_InputService-fx11.apk`（SHA-256 `2a5ad038ef72ab6933e6acfe3cb8b54235a10f82ee5a577864e731145f117882`）通过本机 JADX 离线检查：

1. `InputServiceImpl.getControlIndex()` 调用 `KeyControlUtils.getControlValue()`；该实现通话返回 3，否则返回 2。这不是 MENU 模式，不用于翻页判断。
2. `IDimMenuInteraction` 提供 `onTabChanged`、`onControlCenterStateChanged`、`onVolumeBarStatusChanged` 等回调，未提供当前菜单页签或音量键控制权 getter。`getNaviMode()` 是地图显示类型，不能代替 MENU 状态。
3. SDK 的菜单枚举：0=打开的其他页、1=电话、2=导航、3=音乐、4=控制中心、5=关闭。
4. 200082 未出现在本车输入服务的固定上游按键数组中，因此不能依赖收到 MENU 按键后自行累计开关次数。

“菜单打开对应用户描述的无法调节音量模式”是根据用户实车描述与 SDK 枚举建立的待验证对应，并非已经读取到音量锁定状态。代码先等待真实回调；没有回调时保留 UNKNOWN，不推测初始模式。不能承诺这台车当前固件一定回传对应菜单状态，或 MENU 模式下仍向应用分发上一曲／下一曲。

## 诊断与实车核对

导出诊断中的 Geely wheel 段会包含 `DIM menu`、当前 mode/tab/controlCenter、最近 32 条菜单回调，以及最近一次 track 按键的路由结果。只记录状态，不记录音乐、联系人或导航目的地。

停车时，保持 DiPlay 仪表运行，先确认正常音量模式下上下曲仍切歌；按 MENU 进入原车不能调音量的状态，短按下一曲、上一曲；再按 MENU 退出后复测。导出诊断可区分：接口不支持、无 onTabChanged、状态枚举不符、按键未外发、已成功切页。

本次只连接到模拟器；没有执行实车验收。静态分析并非车辆运行验证。初始状态查询需求受 SDK 限制，采用订阅反馈并等待首次有效事件。
