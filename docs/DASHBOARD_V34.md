# v34 图标状态与音乐封面

## 显示规则

经典仪表的 AutoHold 和手刹固定显示在剩余续航之后、档位之前。
未知/关闭用白色，只有收到明确 true 才用红色；与之前默认隐藏/AutoHold 绿色的规则不同。
未知仍然是未知，白色不证明功能已关闭或车辆已驻车。AutoHold 的 FX11 真实映射尚未确认。
陡坡缓降继续仅在确认开启时出现，不改变灯光颜色和 GPilot 方向盘的状态色。
三套仪表的车道居中确认激活时改白色，未激活/未知保留灰色；车距选中档为白色，未选中为暗色。

## 可复现的封面丢失路径

1. MediaKeys 在已知时长被轻微修正时清除当前封面缓存；同一 transfer ID 时还会取消正在解码的图片。
2. ClusterMusicState 使用严格 title/album/source 相等作为保留条件，与发布端允许标题显示歌词、信息延迟补齐的判断不一致。
3. 失败的重复图片解码会将缓存和当前图片覆盖成 null。

修复：发布端和仪表使用同一封面身份判断，容忍 2 秒以内的时长修正；相同歌曲的标题/歌词更新和首次补齐元信息保留封面。
发布当前已解码 artwork，避免每次进度回调仅查询可能已淘汰的缓存。
相同 ID 的重复图片解码失败不再覆盖有效封面。
真正身份变化仍会清理旧图片；新的 ID 未收到图片时不复用前一首图；同 ID 的标题变化加大幅进度重置仍判定换歌。
旧会话解码结果拒收并回收；断开连接清空。

新增实链路测试通过 mocked controller 驱动实际 MediaKeys 元信息/解码回调并观察 ClusterMusicState：
首张图→延迟元信息与时长修正→200 次歌词/进度→重复解码失败→同 ID 换歌→旧会话回调→新图→新 ID→断开。
渲染测试核对默认白色/激活红色、档位顺序、车道居中白色和三套车距分档。

身份变化日志仅记录引用号、字段变化标记、时长与进度，不记录歌名、歌手或封面内容。
