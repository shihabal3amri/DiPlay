# v35：制动图标颜色与封面生命周期

## 显示规则

经典仪表底部的 AutoHold、手刹维持固定位置：剩余续航 → AutoHold → 手刹 → 档位。
未知或关闭均用灰色；只有读取到明确 true 时，AutoHold 绿色、手刹红色。
灰色不表示已证明关闭。AutoHold 的 FX11 映射仍未确认，不从档位、车速或刹车踏板推断。
延续 v34 的白色车距/车道居中显示规则以及三套仪表、普通 CarPlay、地图和认证配置。

## 已复现并修复的封面清空

`DashboardArtworkDeliveryTest` 在旧实现上失败：新 transfer ID → 新封面解码并显示 →
延迟到达的新歌手/专辑/时长。最后一步把已显示的封面置为 null。
原因是 NowPlaying 属于增量协议，切歌时保留字段可能仍是上一首的值；
不能把后续每一次歌手/专辑/时长修正都当成一次新的封面失效。

现在以图片引用为主要边界；歌词、歌手/专辑补齐或临时空值、时长（含零值）修正不删除同引用图片。
引用变化、完整清空音乐信息、明确切换播放器，及同引用下“非空标题改变且播放进度从 >15s 回到 <3s”仍清除旧图。
保留重复解码失败保护和断开连接清空，旧会话结果不能覆盖新会话。
协议引用可以复用，上述同引用换歌识别仍是启发式，尚无本次车机日志证明现场触发路径；
新增接收/解码/清空/保留日志，便于实车诊断。不新增歌词、歌曲名或图片内容日志。

## DIM 与自定义仪表的图片所有权

封面不是一次性链接或只能读一次的输入流。CarPlay 压缩字节解码后，HUD 使用内存 Bitmap；
DIM 使用独立缩略 Bitmap 和公共目录里的 JPEG 文件。读取文件不会消费或删除源图。
此前已经有 DIM 副本，但歌曲/歌词 revision 更新会反复生成 JPEG，并轮转删除旧文件。

增加 DimArtworkCache：只在源 Bitmap 或内容 generation 改变时生成独立缩略图和文件；
同一封面的歌词/进度更新保持同一 URI。外部读者即使释放 DIM 副本也不影响 HUD 源图。
不手动回收仍可能被元数据读者持有的输出 Bitmap；替换时交由 GC 按引用生命周期回收。
DIM 播放进度继续通过 updateMusicPlayback 更新，不再每半秒重复推送相同播放列表。
仅在元数据成功发送后去重，OEM 服务尚未就绪时保留后续重试机会。
公共文件访问权限与目录保持原有策略，不假定 OEM 已获读取权限。
