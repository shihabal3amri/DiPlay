# v44 无线音乐与仪表重绘优化测试版

## 使用
覆盖安装 v44，打开 DiPlay 并重新连接 CarPlay。对已启用博越 L / FX11 适配的安装，首次启动将无线音乐缓冲设为 1000ms，并固定原来的 USB 缓冲值，不再跟随无线变化。该迁移只执行一次，之后仍可在设置→音频→音乐缓冲（无线）选回300/500ms。较大的音乐缓冲可能增加播放／暂停的响应延迟；导航语音、电话和 Siri 仍使用原低延迟缓冲。未自动启用“缓冲音乐（实验性）”，不改变音频通道和热点配置。

## 重绘优化
- 经典仪表两块圆盘的刻度、渐变、刻度文字和活动弧线使用每圆盘一份 Picture 显示列表；速度／转速或日夜配色改变才重新记录。数字车况、音乐封面和滚动文字继续实时绘制。地图视频不缓存、不降分辨率、不降帧。
- 当车况仅更新时间戳而数值未变化时，不再强制重绘；未知值、数值变化、导航／封面更新、页面和配色切换仍立即响应。
- 长歌名、歌手的1.5秒首尾停留不再每33ms重绘；文字移动时保持约30fps。多个滚动文本共用一个下一帧回调，卸载仪表时移除回调和缓存。
- 地图TextureView缩放矩阵只在尺寸或用户缩放选项变化时更新。

## 音频改进与诊断
- 发现原音频诊断回调在播放线程同步追加SessionLogFile；文件达到512KiB时，该线程还可能执行日志轮转复制。现在所有音频诊断进入既有有界后台队列，音频线程不等待文件I/O。此问题是已确认的代码阻塞风险，尚不能断言是本次每30秒卡顿的实车根因。
- 每5秒单独输出短行“Audio: health”，包含到包最大间隔、压缩队列等待、工作线程循环最大间隔、PCM剩余缓冲／目标缓冲、underrun增量、累计重缓冲、实际播放速率、时钟校正启用状态。独立短行避免关键计数被原700字符导出限制截断。
- 重缓冲事件增加收到最后数据多久、队列／线程耗时和恢复暂停时长。workerCycleMaxMs包含正常阻塞写入时间，不能单凭数值直接断言CPU问题；应和maxWriteMs、receiveGapMaxMs、queuePackets联合分析。
- 仪表保留最近120条内存性能记录：UI绘制命令耗时、绘制次数、圆盘重建次数、250ms车况更新回调延迟。记录随现有诊断导出，不记录歌曲、路线、PCM、协议载荷或认证。UI绘制耗时不等于GPU端到端帧耗时。
- 导出增加异步日志队列积压和丢弃计数；记录过载时有界丢弃，不阻塞音频。

## 验证边界
保留三套自定义仪表、原厂叠加、普通CarPlay、v43自动配色及认证。未改变未确认的AutoHold/车道居中数据映射。
实体FX11暂未连接；本地测试、lint、APK构建与签名／认证／运行库一致性校验见verification.json，不能据此宣称实车卡顿已消除。

安装后保持无线CarPlay＋导航＋仪表＋Apple Music播放3–5分钟；如果仍卡，记下大致时刻，随后立即设置→诊断导出。日志可用同一墙上时间对齐Audio与Dashboard记录。
