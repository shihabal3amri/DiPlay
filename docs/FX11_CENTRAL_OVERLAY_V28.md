# FX11 中央叠加测试版 v28

本次目标是将普通 CarPlay 的地图、导航和音乐放在原厂仪表中央，保留原厂左右圆盘。Android 实现与本地测试已具备；最终 QNX/仪表合成是否保留原厂圆盘仍需实车验证，不能用 Android 截图替代验收。

## 参考与实现边界

复用已有 AutoDisplay 静态分析所证实的物理屏 `WindowManager`、2038 窗口、透明像素格式和独立输出选择思路。旧版 `tn.java:654–681` 创建透明覆盖窗口，`ScreenConfig` 保存明确的 Android display ID；`lw.java` 将窗口配置与 DIM 0/3 请求分开。没有复制、加载或执行第三方 APK 的程序。

AutoDisplay 4.3.9 还包含 HAB/QNX 输出入口及原厂背景控制说明，但 HAB 统一服务标注为银河 L6/L7，匹配 FX11 的接收端、原厂节点控制载荷和最终透明合成没有得到验证。本版没有移植这些未知载荷，也不宣称已经解决底层合成。

v24/v25 在显示屏 4、模式 3 下均出现黑底且原厂圆盘消失。因此本版改变两个条件供实车对比：

- 真正创建中央 720×478 窗口，物理坐标 x=600、y=48；不再创建 1920×532 的透明全屏窗口。左右 600 像素没有本应用窗口覆盖。
- 默认“保留原厂模式”：用户按 MODE/点击开关后，先读取并确认 DIM 状态 0；若旧版遗留 3，只发送一次恢复 0 并等待回读。成功后才创建中央窗口。此路径永远不发送 3。

这两个改动减少了应用覆盖范围，并避免默认进入已观察到圆盘消失的模式 3；不代表 Android 之外的显示链路已确认支持共存。

## 设置及操作

选择博越 L → 本地仪表样式 → 原厂仪表叠加（实验性）。保留原厂模式、屏幕 4 为默认值，默认页为全部信息；选择样式后重新连接普通 CarPlay。按 MODE 或点击叠加开关开启/关闭中央窗口。

如果圆盘保留但中央没有内容，选择屏幕 3，再按 MODE 开启。屏幕 3/4 是 Android 输出编号，不是 QNX 目标编号；只接受可用、公开、亮屏且 1920×532 的仪表输出。失去输出时移除窗口，不自动换到另一块屏幕，也不在输出恢复时自动打开。

“DIM 叠加兼容测试”保留明确请求 0/3 的旧路径，用于必要的对比。它可能再次隐藏原厂圆盘；按 MODE 恢复。更换方式/输出时，如果应用持有叠加请求或正在显示原厂模式窗口，先确认原厂状态 0，再保存新选择和关闭窗口；恢复失败保留旧设置。更换后需要再次开启，不自动请求新通道。切换设置期间忽略重复请求，不写保活循环。

进程重启后原厂模式中央窗口默认关闭，需要明确开启。旧版的“需要恢复”标记保留，恢复成功后才清除。已有三套完整仪表仍使用原先的屏幕选择和 ECARX 0/1 开关。

## 内容与数据

中央上方为导航指令，中间为实时地图，下方为封面/歌曲/歌手；使用已有普通 CarPlay 地图流与会话数据，不依赖 Ultra。全部、导航、音乐三个页面和既有 MENU 翻页逻辑继续可用。

- 导航文字无数据时不画卡片，地图区域向上扩展。
- 音乐元数据无数据时不画卡片，地图区域向下扩展。
- 没有新地图帧时 TextureView 的 alpha 为 0；断开/新会话仍需新帧才显示，避免黑色空纹理或旧地图。
- 使用裁剪坐标而不是将整套仪表缩到中央窗口，文字、地图比例保持正常。
- 原厂车速、转速、灯光、档位和车况由原厂负责，中央模式不绘制重复车况。
